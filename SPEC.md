# Спецификация

## Что делаем

Тестируем готовое приложение «ГРАММ» (`index.html`) в роли тестировщика: находим и
документируем проблемы, код не правим.

## Для кого и зачем

Обычный пользователь приложения — человек, который сам считает калории и БЖУ (как
описано в `sessions/session-1.md`). Цель захода — убедиться, что четыре основных
сценария, их состояния и адаптивная вёрстка работают так, как задумано, и
зафиксировать расхождения.

## Сценарии

1. **Калькулятор порции** — выбрать ингредиент и граммовку, добавить в список;
   изменить граммы у уже добавленной строки; удалить строку; очистить весь список;
   сохранить состав как рецепт с названием.
   *(добавлено после сессии 3)* Выбор ингредиента — через комбобокс с поиском:
   ввод подстроки фильтрует выпадающий список, выбор — кликом по пункту (не
   произвольным текстом). При добавлении в порцию — переключатель единиц «г»
   или «шт»; «шт» переводится в граммы через заданный вес одной штуки
   ингредиента.
2. **База ингредиентов** — добавить новый ингредиент (название + ккал/Б/Ж/У на
   100 г); отредактировать существующий, включая предзагруженные; удалить
   ингредиент.
   *(добавлено после сессии 3)* Необязательное поле «Вес 1 шт, г» при создании
   и редактировании ингредиента, отображается отдельным столбцом таблицы базы.
3. **Рецепты** — открыть/свернуть карточку рецепта; посмотреть пересчитанные
   итоги; загрузить рецепт обратно в калькулятор; удалить рецепт.
4. **Подбор блюд под БЖУ** — задать целевые ккал/Б/Ж/У (0 = не важно); увидеть
   список рецептов, отсортированный по проценту совпадения, с разницей по каждому
   показателю.
5. **Адаптивная вёрстка** — те же сценарии на узком экране (ниже брейкпоинта
   860px, где сайдбар и раскладка перестраиваются).

## Состояния

- **Калькулятор:** список пуст (плейсхолдер-строка, кнопка «Сохранить рецепт»
  неактивна) · база ингредиентов пуста (подсказка «сначала добавьте ингредиент»,
  выбор и кнопка «Добавить» задизейблены) · есть данные (суммы и макро-полоса
  посчитаны) · ошибка ввода (0 или отрицательные граммы — фокус на поле без
  добавления; пустое название рецепта — фокус без сохранения).
  *(добавлено после сессии 3)* Комбобокс поиска: подстрока без совпадений
  (пустой список/подсказка) · текст введён, но пункт не выбран кликом (что
  происходит при попытке нажать «Добавить») · текст поля стёрт после выбора
  (выбор сбрасывается, повторно нельзя добавить без нового клика по списку) ·
  опция единицы «шт» задизейблена, если у выбранного ингредиента вес 1 шт не
  задан.
- **Ингредиенты:** список пуст (заглушка «Ингредиентов пока нет») · есть данные ·
  ошибка ввода (пустое название — фокус без добавления; нечисловые БЖУ
  трактуются как 0).
  *(добавлено после сессии 3)* Поле «Вес 1 шт, г» пустое или 0 трактуется как
  «не задано» (в калькуляторе опция «шт» для такого ингредиента недоступна).
- **Рецепты:** нет рецептов (подсказка) · есть рецепты (карточки) · предупреждение
  (ингредиент внутри рецепта удалён из базы — плашка-предупреждение и «Ингредиент
  удалён из базы» вместо строки).
- **Подбор блюд:** нет сохранённых рецептов (подсказка) · есть результаты,
  отсортированные по близости · все цели = 0 (нейтральный «—», сортировка по
  алфавиту).

## Чего точно не делаем

- Кроссбраузерность — тестируем только в Chrome, остальные браузеры вне охвата.
- Глубокие технические граничные случаи вне «типичных ошибок ввода»: XSS в
  названиях, экстремально большие числа, поведение при переполненном/отключённом
  localStorage — в этот заход не входят.
- Пиксель-перфект дизайна (цвета, отступы, шрифты как таковые) не оцениваем —
  только функциональные баги вёрстки.
- Поиск/фильтр по таблице базы ингредиентов на вкладке «Ингредиенты» — решено
  не делать (см. «Открытые вопросы»).
- Редактирование уже добавленной строки состава порции/рецепта в единицах
  «шт» — решено не делать, редактирование остаётся в граммах (см. «Открытые
  вопросы»).

## Допущения

- Тестируем локальным открытием `index.html` в браузере, без сервера и без
  сборки — так и задуман проект.
- Раунд ручной, без автотестов — их в проекте нет.
- Адаптив проверяем на ширинах вокруг брейкпоинта 860px и на типичном мобильном
  разрешении.

## Открытые вопросы

Закрыты на этапе составления спецификации:
- Проверяем ли адаптив в этом заходе — да.
- Браузер — Chrome.
- Куда фиксировать баги — отдельный файл `BUGS.md`.

Закрыты после сессии 3 (уточнено у пользователя перед раундом тестирования
сессии 4):
- Поиск/фильтр по таблице базы ингредиентов на вкладке «Ингредиенты» — не
  нужен, в объём тестирования и доработки не входит.
- Редактирование уже добавленной в порцию/рецепт строки в единицах «шт» — не
  нужно, редактирование строки остаётся только в граммах, это не дефект.

Открыт (обнаружено в сессии 4, ручной прогон тест-плана, ждём решения):
- Комбобокс поиска ингредиента: пользователь вручную набирает текст, точно
  совпадающий с названием существующего ингредиента, но не кликает по пункту
  выпадающего списка, затем нажимает «Добавить». Фактически: ничего не
  добавляется, фокус молча возвращается в поле поиска — без текста ошибки,
  без подсветки поля. Технически это тот же паттерн, что уже принят в проекте
  для числовых полей (0/отрицательные граммы — «фокус на поле без добавления»
  без текста ошибки), поэтому не заводим как дефект сходу — но здесь
  пользователь мог и не подозревать, что выбор не подтверждён (текст в поле
  выглядит как готовое значение). Не знаем, ожидаемое ли это поведение или
  нужна явная подсказка/подсветка — решение за пользователем проекта.
