# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-16 · Сессия 4 · `@playwright/test` — попытка не удалась

- **Тип:** библиотека (тестовый фреймворк)
- **Установка:** `npm install --no-audit --no-fund @playwright/test` — завершилась
  ошибкой `403 Forbidden` от `registry.npmjs.org`: в песочнице тестировщика запрещена
  установка новых npm-пакетов.
- **Зачем:** хотел писать автотест дефекта №2 через стандартный `@playwright/test`
  (`test()`/`expect()`, встроенный раннер и репортер).
- **Область:** проект (локально в `package.json`).
- **Проверка:** не потребовалась — установка не прошла, тупиковая попытка.
- **Итог:** снято, заменено на `playwright` (базовый пакет, уже доступен в окружении,
  использовался в сессиях 3–4 для ручных проверок) + встроенный модуль Node
  `node:assert/strict`. Функционально даёт то же самое (тест падает с понятной
  ошибкой и ненулевым кодом возврата на дефектном коде), просто без готового
  раннера/репортера `@playwright/test`.

## 2026-08-16 · Сессия 4 · `playwright` (Node-пакет) — первый формальный автотест проекта

- **Тип:** библиотека
- **Установка:** не устанавливался отдельно — уже доступен глобально в окружении
  тестировщика (использовался и раньше, в сессиях 3–4, для ручных Playwright-скриптов
  на Python; здесь впервые оформлен как Node-тест с проверкой и кодом возврата).
- **Зачем:** написать первый автотест проекта (`tests/defect-02-pcs-label-rounding.test.js`)
  для дефекта №2 из `BUGS.md`, воспроизводящий его на текущем коде.
- **Область:** проект (`tests/`, `package.json` с зависимостью `playwright` — без
  закоммиченного `node_modules`, ставится через `npm install playwright && npx
  playwright install chromium`).
- **Проверка:** тест запущен (`node tests/defect-02-pcs-label-rounding.test.js`) —
  красный на текущем `index.html` (см. `sessions/session-4.md`). Дополнительно
  проверено на временной пропатченной копии файла вне проекта, что тест зеленеет,
  если исправить дефект — то есть тест не «красный всегда», а проверяет именно
  найденную проблему.

## 2026-08-16 · Сессия 4 · Python `playwright` — второй вариант автотеста дефекта №2

- **Тип:** библиотека
- **Установка:** не устанавливался отдельно — Python-пакет `playwright` уже был в
  окружении и использовался в этой же сессии для прогона тест-плана (`run_tests.py`,
  `run_tests2.py`).
- **Зачем:** по просьбе пользователя переписать Node-автотест
  (`tests/defect-02-pcs-label-rounding.test.js`) на Python — тот же дефект №2, тот же
  сценарий воспроизведения. `pytest`/`pytest-playwright` не ставил: раз в среде
  тестировщика уже запрещена установка новых npm-пакетов, не стал напрашиваться на то
  же самое с pip ради обвязки, без которой можно обойтись — обычный `assert` +
  код возврата дают ту же красную/зелёную проверку.
- **Область:** проект (`tests/defect-02-pcs-label-rounding.test.py`).
- **Проверка:** тест запущен (`python3 tests/defect-02-pcs-label-rounding.test.py`) —
  красный на текущем `index.html`, вывод — `tests/defect-02-run-output-python.txt`.
  Повторно проверено на временной пропатченной копии `index.html` вне проекта (не в
  файле самого проекта), что тест зеленеет при исправлении — тест содержательный, а не
  «красный по построению».
