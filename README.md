# ГРАММ — лаборатория рациона

Одностраничное веб-приложение для учёта питания: калькулятор порции (ккал/БЖУ),
база ингредиентов, рецепты, подбор блюд под целевые БЖУ. Чистый HTML/CSS/JS,
без сборки и без бэкенда — все данные хранятся в `localStorage` браузера.

## Как запустить

Файл самодостаточный, сборка не нужна.

**Вариант 1 — просто открыть файл** (быстрее всего, подходит для обычного
использования):

```
двойной клик по index.html
```

**Вариант 2 — через локальный сервер** (так тестировали в ходе разработки —
`fetch`/некоторые API ведут себя ближе к реальному хостингу, чем на `file://`):

```bash
python3 -m http.server 8765
# затем открыть http://localhost:8765/index.html
```

Требования: любой современный браузер. Разработка и тестирование велись
только в Chrome/Chromium — другие браузеры не проверялись (см. «Допущения»).

### Автотесты

Есть один автотест (на два стека, дублирует один и тот же сценарий), покрывает
только дефект «подпись «шт» округляет вес до целого» — см. «Что не сделано».

```bash
# поднять стенд в одном терминале
python3 -m http.server 8765

# в другом терминале
npm install playwright && npx playwright install chromium
node tests/defect-02-pcs-label-rounding.test.js
# или
python3 tests/defect-02-pcs-label-rounding.test.py
```

Оба теста красные на текущем коде (баг воспроизведён, не исправлен полностью —
подробности ниже).

## Что сделано

- **Калькулятор порции** — поиск ингредиента через комбобокс (фильтрация по
  подстроке, без учёта регистра), добавление по количеству в граммах или в
  штуках (если у ингредиента задан вес одной штуки), редактирование граммовки
  уже добавленной строки, удаление строки, очистка списка, сохранение состава
  как именованного рецепта.
- **База ингредиентов** — 20 предзагруженных продуктов, добавление/редактирование/
  удаление любых записей (включая базовые), необязательное поле «Вес 1 шт, г».
- **Рецепты** — сохранение, просмотр с раскрытием карточки, пересчёт при
  изменении базы ингредиентов, предупреждение, если ингредиент рецепта удалён
  из базы, загрузка рецепта обратно в калькулятор, удаление.
- **Подбор блюд под БЖУ** — целевые ккал/Б/Ж/У (0 = не важно), сортировка
  рецептов по проценту совпадения с целью.
- **Адаптивная раскладка** — сайдбар и часть сеток перестраиваются на ширинах
  ≤860px (частично — см. известные баги).

## Что не сделано / что упростили

Без прикрас — то, что осталось за рамками или не работает как задумано:

- **Поиск/фильтр по таблице базы ингредиентов** (вкладка «Ингредиенты») — не
  делали. Реализован только поиск при *выборе* ингредиента в калькуляторе;
  сама таблица базы фильтра не имеет. Решение принято сознательно, не забыто.
- **Редактирование уже добавленной строки состава в единицах «шт»** — строка
  состава порции/рецепта редактируется только в граммах, даже если изначально
  была добавлена как «шт». Осознанное упрощение — не стали хранить единицу для
  каждой строки и обратный пересчёт.
- **Кроссбраузерность** — тестировали только Chrome/Chromium. Firefox, Safari
  и мобильные браузеры не проверялись вообще.
- **Клавиатурная навигация комбобокса поиска** — не реализована и не
  проверялась. Работает только мышью (стрелки/Enter/Esc не задействованы).
- **XSS в названиях, экстремально большие числа, поведение при переполненном/
  отключённом localStorage** — вне охвата тестирования, не проверялись.

### Известные баги (не исправлены)

- **[minor] Очень длинное название ингредиента ломает вёрстку таблицы базы.**
  Валидации длины названия нет; при вставке названия ~370 символов без
  пробелов строка таблицы «Список ингредиентов» уезжает далеко за пределы
  карточки (`scrollWidth` 3053px против `clientWidth` 898px), часть колонок и
  кнопок «Изменить»/«Удалить» становятся недостижимы без горизонтального
  скролла, которого в интерфейсе нет.
- **[minor] Тот же класс бага — в выпадающем списке комбобокса поиска
  ингредиента** (вкладка «Калькулятор»). Не задокументирован как отдельная
  запись в `BUGS.md`, обнаружен позже как повтор известного риска: имя такой
  же длины в пункте списка растягивает его до `scrollWidth` ~2600px при
  видимой ширине поля ~460px — без визуальной подсказки, что список
  скроллится по горизонтали.
- **[major] На узких экранах (≤480px) калькулятор и вкладка «Ингредиенты» не
  вписываются в ширину экрана.** Кнопка «Добавить» в калькуляторе целиком
  уезжает за правый край на ширине 375px; на вкладке «Ингредиенты»
  `body.scrollWidth` держится на 662px независимо от ширины окна — контент
  технически достижим через скролл/масштабирование, но неудобен. Затронуты
  оба места, добавленные/расширенные функциональностью поиска и учёта штук.
- **Дефект «подпись «шт» округляет вес одной штуки до целого» исправлен
  только частично.** В калькуляторе (селектор единиц измерения) подпись
  теперь корректно показывает дробный вес (например, «шт (0,1 г/шт)»). Но
  ровно тот же код форматирования без десятичных знаков остался в столбце
  «1 шт, г» таблицы «Список ингредиентов» на вкладке «Ингредиенты» — там
  вес 0,1 г по-прежнему отображается как «0». Автотест (`tests/`) проверяет
  только исправленное место (калькулятор), не таблицу базы — значит вторая
  половина бага автотестами не покрыта.
- **Открытый вопрос, не решён:** если ввести в поиск текст, точно совпадающий
  с названием ингредиента, но не кликнуть по пункту списка, а сразу нажать
  «Добавить» — ничего не добавляется, фокус молча возвращается в поле, без
  текста ошибки. Технически совпадает с уже принятым в проекте паттерном для
  числовых полей, но неочевидно для пользователя (текст в поле выглядит как
  готовый выбор). Не заведено ни как баг, ни как норма — ждёт решения.

## Допущения

- Данные хранятся только в `localStorage` браузера — без бэкенда, без синхронизации
  между устройствами и браузерами; очистка данных сайта в браузере удаляет всё.
- У 20 стандартных ингредиентов вес одной штуки по умолчанию не задан — опция
  «шт» для них недоступна, пока пользователь не впишет вес вручную через
  «Изменить».
- Единицы «шт» переводятся в граммы один раз, в момент добавления в состав —
  дальше строка живёт только в граммах (см. «Что не сделано»).
- Тестовый стенд — `python3 -m http.server 8765`, тестовый браузер — Chrome/
  Chromium. Автотесты используют голый `playwright` (без `@playwright/test` —
  пакет не удалось установить в песочнице тестировщика, см. `sessions/TOOLS.md`).

## Структура проекта

```
index.html          — приложение (единственный файл с кодом)
AGENTS.md            — правила работы над проектом (курс + настройки проекта)
SPEC.md              — спецификация: сценарии, состояния, допущения, открытые вопросы
BUGS.md              — журнал найденных дефектов
TEST-PLAN.md         — утверждённый тест-план (12 проверок по функциональности поиска/штук)
tests/               — автотесты (Node + Python, оба воспроизводят один и тот же дефект)
sessions/            — журнал работы по сессиям (STATE.md, TOOLS.md, session-N.md)
screenshots/         — доказательства найденных дефектов
```
